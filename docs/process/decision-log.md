- 2026-06-25: Keep the product centered on a Three.js globe interface, `ai-elements`-style assistant components, and Supabase-aligned schema design.
- 2026-06-28: Build the personalized OSINTel as a separate branch and in-app surface (a "My" tab + `/api/personal/*` namespace), leaving the general feed and routes unchanged.
- 2026-06-28: Port the lifescience-research-copilot retrieval and zero-hallucination logic to TypeScript inside the Express server rather than shelling out to the Python `review.py`, to keep the single-Node-process deployment model and reuse existing types and the multi-provider LLM proxy.
- 2026-06-28: Keep the research surface de-identified: only derived gene/cancer tokens are sent to external APIs (Europe PMC, ClinicalTrials.gov); no PatientProfile PII leaves the device.
- 2026-07-02: Adopt an explicit runtime mode contract for production hardening: `real`, `graceful_fallback`, `demo_only`, and `unavailable`. Production-facing APIs must not insert simulated medical content into real feed or chat state when upstream search/model providers are unavailable.
- 2026-08-08 (#9): Build the 胰腺中心信息库 as independent collections (hospitals/doctors/services) rather than extending the existing flat ResourceCenter model. This keeps backward compatibility and allows phased migration. Use in-memory arrays in server.ts (mirroring existing osintFeed/resourceCenters patterns) for API serving, with Firestore CRUD modules (`src/lib/centers/*-crud.ts`) ready for future cloud persistence. Keep community contribution simple with a pending→approve/reject two-state workflow instead of multi-level review. Use a custom quality scoring engine (factory pattern, following `credibility/engine.ts`) with 5 weighted dimensions rather than ML-based scoring for v1. Frontend search/filter is client-side via useMemo (data volume <500 entries), matching existing OSINT feed patterns. The globe/map view is simplified to city-grouped cards instead of a full 3D projection, deferring the Three.js integration to a later phase.
- 2026-08-08 (#9): Follow the existing project testing pattern of using Node.js built-in `node:test` (describe/it blocks) with pure-function mirrors for unit tests and spawned server processes for API integration tests, matching the credibility/dedup/e2e test conventions. All center tests (100 total) use the same `{ status, data }` response envelope validated across 7 test files.
